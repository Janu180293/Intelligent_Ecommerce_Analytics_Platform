# Intelligent E-Commerce Customer Analytics Platform — Deployment Guide

## What this is
An end-to-end analytics platform built on the Brazilian Olist e-commerce dataset:
data integration → cleaning → EDA → feature engineering → customer segmentation →
purchase prediction → CLV prediction → recommendations → SHAP explainability →
Streamlit dashboard.

**Honesty note on deployment:** this guide gives you the exact, tested steps to run
the app locally and deploy it to Streamlit Community Cloud (the standard free hosting
route named in the project spec). I ran and verified every notebook/script and smoke-
tested `app.py` in this sandbox, but I do **not** have the ability to reach the public
internet from here to actually push to GitHub or click through Streamlit Cloud's
UI on your behalf — those last two steps need to happen from your machine/account.

## 2. Local setup

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r src/requirements.txt
```

## 3. Run the pipeline (must run in this order — later phases depend on earlier outputs)

```bash
cd src

# Phase 1-2: ETL (plain scripts)
python 01_data_integration.py
python 02_data_cleaning.py
python 04_feature_engineering.py

# Phase 3, 5-9: notebooks — run each top-to-bottom in Jupyter, or execute headlessly:
jupyter nbconvert --to notebook --execute --inplace 03_eda.ipynb
jupyter nbconvert --to notebook --execute --inplace 05_segmentation.ipynb
jupyter nbconvert --to notebook --execute --inplace 06_purchase_prediction.ipynb
jupyter nbconvert --to notebook --execute --inplace 07_clv_prediction.ipynb
jupyter nbconvert --to notebook --execute --inplace 08_recommendation_system.ipynb
jupyter nbconvert --to notebook --execute --inplace 09_explainability.ipynb
```

Each script/notebook reads from `../outputs/` and writes back to it — this is why
order matters. Every artifact `app.py` needs (models, CSVs, SHAP images) is produced
by phase 6 through 9 notebooks.

## 4. Run the dashboard locally

```bash
cd src
streamlit run app.py
```
Opens at `http://localhost:8501`.

## 5. Deploy to Streamlit Community Cloud (free, matches the "Streamlit" deployment
   target named in the project spec)

1. Push this whole `project/` folder (including the populated `outputs/` directory —
   Streamlit Cloud has no way to run your pipeline scripts for you, so the pipeline
   outputs need to already exist in the repo, or be regenerated by a startup script)
   to a **public or private GitHub repository**.
   - `outputs/` contains large CSVs (some 20-30MB) and two `.joblib` model files.
     GitHub's soft file-size limit is 50MB per file and repo-wide practical limits
     apply — if this becomes an issue, consider **Git LFS** for the CSVs, or have
     `app.py` regenerate `outputs/` on first boot (see note below).
2. Go to **https://share.streamlit.io** and sign in with GitHub.
3. Click **"New app"**, select your repository, branch, and set the main file path
   to `src/app.py`.
4. Under **Advanced settings**, set the Python version to match your local one
   (3.11+ recommended) and add `src/requirements.txt` as the requirements file.
5. Click **Deploy**. Streamlit Cloud will install dependencies and launch the app;
   you'll get a public URL like `https://<your-app-name>.streamlit.app`.

**If repo size is a problem:** the cleanest fix is to make `app.py`'s data loaders
fall back to running the pipeline scripts if `outputs/` is missing on first boot
(a few minutes of one-time compute on Streamlit Cloud's free tier). This wasn't
built into `app.py` by default to keep dashboard startup fast for local dev, but
it's a small addition if you need it — happy to add it if you tell me you're
hitting this.

## 6. Alternative hosting (if Streamlit Cloud doesn't fit your needs)
- **AWS**: EC2 + `streamlit run app.py --server.port 80` behind a security group,
  or containerize with Docker and run on ECS/Fargate (project spec lists AWS as a tag).
- **Render / Railway / Fly.io**: all support a `Dockerfile`-based Streamlit deploy
  with a free/low-cost tier, if you'd prefer not to use Streamlit Cloud specifically.

## 7. Known limitations to disclose (carried over from earlier phases)
- Phase 6 (purchase prediction) and Phase 7 (CLV prediction) models have weak
  absolute performance (ROC-AUC ~0.5-0.57, R² ≈ 0) — this is a genuine property of
  the Olist dataset (extremely low repeat-purchase rate within any 90-day window),
  documented with full transparency in each notebook's "Key takeaways" section.
  The dashboard surfaces this caveat directly next to each prediction.
- Phase 8 (recommendations) performs well on customers with repeat-category
  purchase history, but relies on content-based fallback for the ~95% of
  customers who bought only once — also disclosed in-app.
