# 🛍️ Intelligent E-Commerce Customer Analytics Platform

An end-to-end customer analytics platform built on the [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce): data integration → cleaning → EDA → feature engineering → customer segmentation → purchase prediction → CLV prediction → product recommendations → SHAP explainability → an interactive Streamlit dashboard.

## Overview

Modern e-commerce platforms generate enormous transactional data, but data alone doesn't drive growth. This project turns raw Olist marketplace data into a unified system that segments customers, predicts behavior, and recommends products — so marketing and business teams can act on it through one dashboard.

**Scale:** 96,096 unique customers · 99,441 orders · 32,216 products · 27 Brazilian states · R$ 15.4M in tracked revenue.

## Key Results

| Phase | Result |
|---|---|
| **Customer Segmentation** | K-Means (k=5), silhouette score **0.359** → 5 actionable segments: Premium, Regular, Bargain Hunters, New Customers, Dormant |
| **Purchase Prediction** | 6 models compared (Logistic Regression → XGBoost/LightGBM). Best ROC-AUC **0.567**. See [Honest findings](#honest-findings) below. |
| **CLV Prediction** | 5 regression models compared. R² ≈ 0. See [Honest findings](#honest-findings) below. |
| **Recommendation Engine** | Content-based, item-based CF, SVD matrix factorization, and a hybrid blend. Hybrid reaches **95.4% Hit Rate@5** on customers with repeat-category purchase history. |
| **Explainability** | Full SHAP suite (summary, bar, waterfall, force plots) for both the purchase and CLV models — every prediction is auditable back to its driving features. |

### Honest findings

Only **~0.7% of existing customers repurchase within any given 90-day window** in this dataset — Olist is overwhelmingly a one-time-purchase marketplace. That's why the purchase-prediction and CLV models land at modest absolute scores (AUC ~0.5–0.57, R² ≈ 0): this is a genuine, disclosed property of the data, not a bug in the pipeline. Each notebook documents the finding in detail and proposes concrete next steps (wider prediction windows, two-stage modeling, additional signal sources). The dashboard surfaces this caveat directly next to each prediction rather than hiding it.

## Setup

```bash
git clone <your-repo-url>
cd project
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r src/requirements.txt
```

Download the [Olist dataset from Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) and place the 9 CSVs in `data/`.

## Run the Pipeline

Order matters — each phase reads the previous phase's output from `outputs/`.

```bash
cd src

# Phases 1, 2, 4 — plain ETL scripts
python 01_data_integration.py
python 02_data_cleaning.py
python 04_feature_engineering.py

# Phases 3, 5-9 — notebooks (run top-to-bottom in Jupyter, or headlessly:)
jupyter nbconvert --to notebook --execute --inplace 03_eda.ipynb
jupyter nbconvert --to notebook --execute --inplace 05_segmentation.ipynb
jupyter nbconvert --to notebook --execute --inplace 06_purchase_prediction.ipynb
jupyter nbconvert --to notebook --execute --inplace 07_clv_prediction.ipynb
jupyter nbconvert --to notebook --execute --inplace 08_recommendation_system.ipynb
jupyter nbconvert --to notebook --execute --inplace 09_explainability.ipynb
```

## Run the Dashboard

```bash
cd src
streamlit run app.py
```
Opens at `http://localhost:8501` with 5 pages: **Executive Dashboard**, **Customer Analytics**, **Recommendation Engine**, **Business Insights**, **Explainability**.

## Deployment

**Streamlit Community Cloud (recommended, free):**
1. Push this repo to GitHub, including the populated `outputs/` directory (Streamlit Cloud can't run the pipeline for you — the artifacts need to already exist, or be regenerated on first boot).
   - `outputs/` contains large CSVs (20–30MB) and two `.joblib` model files. If you hit GitHub's size limits, use **Git LFS** for the CSVs, or add a first-boot fallback that regenerates `outputs/` from `data/`.
2. Go to [share.streamlit.io](https://share.streamlit.io) and sign in with GitHub.
3. **New app** → select this repo/branch → main file path `src/app.py`.
4. Under **Advanced settings**, set the Python version (3.11+) and point to `src/requirements.txt`.
5. **Deploy** → you'll get a public URL at `https://<your-app-name>.streamlit.app`.

**Alternatives:** Docker on AWS ECS/Fargate or EC2; Render, Railway, or Fly.io for a `Dockerfile`-based deploy.

## Known Limitations

- **Purchase prediction & CLV models** have low absolute predictive power (see [Honest findings](#honest-findings)) — a structural property of Olist's repurchase rate, not a pipeline defect.
- **Recommendations** perform strongly for customers with repeat-category history (~3% of the base) but fall back to content-based popularity for the ~95% of customers who bought only once (true cold start).
- `customer_id` in the raw Olist data is unique **per order**, not per person — all customer-level aggregation in this project correctly uses `customer_unique_id` instead.
